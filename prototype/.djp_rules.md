# DJP PROTOTYPE OPERATIONAL RULES

## Context Allocation
* Always reference `prototype/.djp_state.md` and `prototype/AGENTIC_WORKFLOW_GUIDE.md` prior to executing tasks.
* Check prototype `/todo.md` (`prototype/todo.md`) for active user intake requests and dispatch to domain todos (`prototype/frontend/fe-todo.md`, `prototype/backend/be-todo.md`, `prototype/tests/test-todo.md`).
* Adhere strictly to lean codebase rules and existing conventions.
* ONLY change files inside the `prototype/` folder. Do not touch production code outside of `/prototype`.

## Anti-Over-Engineering Guidelines
* Do NOT write new custom components or setup new structures from scratch if similar ones exist in the root `/frontend` or `/backend` folders.
* Always copy, import, or adapt existing modules, components, and pages from the production codebase.
* Prefer the smallest, simplest React and Spring Boot solutions that fulfill the prototype's objectives.

## Code Quality Standards
* Ensure the React code inside `prototype/frontend` mirrors production layout/style but remains lightweight.
* Ensure the Spring Boot backend inside `prototype/backend` is clean and reuse-focused.
* Maintain clear structured sections, visual diagrams, and low cognitive load.
