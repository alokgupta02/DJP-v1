# BMAD OPERATIONAL RULES

## Context Allocation
* Always reference `bmad/.djp_state.md` and `bmad/AGENTIC_WORKFLOW_GUIDE.md` prior to executing tasks.
* Check `bmad/todo.md` for active user intake requests and dispatch to domain todos (`bmad/frontend/fe-todo.md`, `bmad/backend/be-todo.md`, `bmad/tests/test-todo.md`).
* Adhere strictly to lean codebase rules and existing conventions.
* ONLY change files inside the `bmad/` folder. Do not touch production code or `prototype/` outside of `bmad/`.

## Anti-Over-Engineering Guidelines
* Do NOT write new custom components or setup new structures from scratch if similar ones exist in `prototype/`, root `/frontend`, or `/backend`.
* Always copy, import, or adapt existing modules, components, and pages.
* Prefer the smallest, simplest React and Spring Boot solutions.

## Code Quality Standards
* Ensure React code mirrors production layout/style but remains lightweight.
* Ensure Spring Boot backend is clean and reuse-focused.
* Maintain clear structured sections, visual diagrams, and low cognitive load.
